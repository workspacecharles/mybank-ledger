# Modelo C4 — MyBank

Diagramas da arquitetura no **modelo C4**, do zoom mais aberto ao mais fechado. As decisões por trás de cada parte estão nos [ADRs](./ADR.md); fluxos, garantias e operação, em [Architecture.md](./Architecture.md).

O modelo C4 tem quatro níveis de zoom: contexto, contêineres, componentes e código. Os três primeiros estão abaixo; o quarto nível (classes) não foi desenhado, porque o próprio código, com um tipo por arquivo, já mostra isso. No C4, **contêiner** é qualquer coisa que roda ou guarda dados separadamente (uma aplicação, um banco), não necessariamente um contêiner Docker.

Legenda: azul-escuro = pessoa; azul = parte do MyBank; cinza = sistema externo.

Quem usa o sistema e com quem ele se relaciona.

## 2. Nível 2: Contêineres

As partes que rodam separadamente e como conversam. API e worker **não se comunicam diretamente**: o único ponto de contato é o banco, pela outbox ([ADR-0003](./adr/0003-outbox-transacional-sem-broker.md)).

```mermaid
flowchart TB
    cliente["<b>Cliente / Administrador</b><br/>[Pessoa ou aplicação]"]
    idp["<b>Provedor de identidade</b><br/>[Sistema externo, OIDC]"]

    subgraph mybank ["MyBank [Sistema]"]
        api["<b>MyBank.Api</b><br/>[Contêiner: ASP.NET Core, .NET 10]<br/>Valida e registra lançamentos, responde<br/>saldo atual, histórico e consolidado"]
        worker["<b>MyBank.Worker</b><br/>[Contêiner: .NET Worker Service]<br/>Lê a outbox em lotes e mantém<br/>a consolidação diária"]
        db[("<b>PostgreSQL</b><br/>[Contêiner: banco de dados]<br/>accounts, ledger_entries,<br/>outbox_messages, daily_balances")]
    end

    cliente -->|"Requisições REST<br/>[HTTPS/JSON + JWT]"| api
    api -.->|"Valida tokens<br/>[HTTPS]"| idp
    api -->|"1 transação: lançamento + saldo + outbox<br/>Lê saldo, razão e consolidado<br/>[SQL/TCP]"| db
    worker -->|"Lê outbox (SKIP LOCKED), grava consolidado<br/>e marca processado no mesmo commit<br/>[SQL/TCP]"| db

    classDef person fill:#08427b,stroke:#052e56,color:#fff
    classDef container fill:#438dd5,stroke:#2e6295,color:#fff
    classDef external fill:#999999,stroke:#6b6b6b,color:#fff
    class cliente person
    class api,worker,db container
    class idp external
```

*Diagrama de Contêineres (C4, nível 2)*

| Contêiner | Escala | Se parar |
|---|---|---|
| `MyBank.Api` | Várias instâncias (sem estado; trava na linha da conta) | Nada é registrado |
| `MyBank.Worker` | Várias instâncias (`SKIP LOCKED` divide a fila) | Lançamentos continuam; o consolidado atrasa e informa o atraso |
| PostgreSQL | Vertical; réplica de leitura e particionamento como evolução | Nada é confirmado; a API responde `503` e o cliente repete com a mesma chave |

## 3. Nível 3: Componentes

As principais partes dentro de cada contêiner. `LedgerService`, `DailyBalanceProjector` e `MyBankDbContext` estão no projeto `MyBank.Core`; `LedgerRules` está no `MyBank.Domain`. API e worker usam os mesmos componentes do `Core`, cada um no seu processo.

```mermaid
flowchart TB
    cliente["<b>Cliente</b>"]
    db[("<b>PostgreSQL</b>")]

    subgraph api ["MyBank.Api [Contêiner]"]
        auth["<b>Autenticação JWT</b><br/>[AuthenticationExtensions, AuthPolicies]<br/>Valida token, titular = claim sub"]
        endpoints["<b>AccountEndpoints</b><br/>[Minimal API]<br/>Rotas /api/v1/accounts, converte<br/>JSON ↔ contratos"]
        health["<b>HealthEndpoints</b><br/>/health/live, /ready, /projection"]
        errors["<b>ErrorHandler</b><br/>Erros → problem+json, banco fora → 503"]
        service["<b>LedgerService</b><br/>[Core]<br/>Casos de uso: transação, trava,<br/>idempotência, gravação"]
        rules1["<b>LedgerRules</b><br/>[Domain]<br/>Regras puras: validação, saldo,<br/>titularidade, chave"]
        ctx1["<b>MyBankDbContext</b><br/>[Core, EF Core]<br/>Repositório + unidade de trabalho"]
    end

    subgraph wk ["MyBank.Worker [Contêiner]"]
        loop["<b>ProjectionWorker</b><br/>[BackgroundService]<br/>Laço: lote → próximo, vazio → 1 s, erro → 5 s"]
        projector["<b>DailyBalanceProjector</b><br/>[Core]<br/>Lê lote da outbox, faz upsert<br/>do dia, marca processado"]
        rules2["<b>LedgerRules.SummarizeDay</b><br/>[Domain]<br/>Resumo do dia, independente de ordem"]
        ctx2["<b>MyBankDbContext</b><br/>[Core, EF Core]"]
    end

    cliente -->|"HTTPS/JSON + JWT"| auth
    auth --> endpoints
    endpoints --> service
    endpoints -.->|"exceções"| errors
    service --> rules1
    service --> ctx1
    health --> ctx1
    ctx1 -->|"SQL"| db

    loop --> projector
    projector --> rules2
    projector --> ctx2
    ctx2 -->|"SQL"| db

    classDef person fill:#08427b,stroke:#052e56,color:#fff
    classDef component fill:#85bbf0,stroke:#5d82a8,color:#000
    classDef container fill:#438dd5,stroke:#2e6295,color:#fff
    class cliente person
    class auth,endpoints,health,errors,service,rules1,ctx1,loop,projector,rules2,ctx2 component
    class db container
```
